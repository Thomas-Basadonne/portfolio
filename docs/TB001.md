# TB-001 integration — #19

## Source and boundaries

TB-001 is an original illustrative concept, not a real product or a physical simulation. Geometry and mechanics follow the approved **#18 spike, SPEC v0.4** ([reference specification](tb001/SPEC.md)), including the 26° rear twist, bottom hatch hinge and outside-in sequential teardown. The approval and measured spike are recorded in [#18 comment 6660534014](https://github.com/Thomas-Basadonne/portfolio/issues/18#issuecomment-6660534014). The integration scope is [#19](https://github.com/Thomas-Basadonne/portfolio/issues/19).

No second canvas, renderer, teardown runtime, global review control, external texture/HDR, dependency or professional-copy change is introduced. DOM, HUD, CSS, entry and controller scheduling are unchanged. The previous `ToleranceMachine`, `ParticleDust` and `ScanField` modules were removed only after the official #12 before/after comparison completed. Their removal leaves the already-reviewed production build byte-identical.

## Contracts

- `src/experience/tb001/pose.ts`: `pose(cycle, explode, t)` allocates a fresh pure pose; `createPose`/`writePose` fill a reusable pose tree with the same values and stable part IDs. Inputs outside `[0,1]` are clamped; NaN progress becomes zero; nonfinite time becomes zero. The committed JSON fixtures were generated from the approved spike, not invented.
- `machine.ts`/`shell.ts`: `createMachine({ quality, textures })` builds named geometry once. `update(pose)` mutates transforms, shared colors, uniforms and instanced buffers without rebuilding geometry/materials/textures. Dynamic instance bounds are refreshed so the shell rivets and orbit nodes cannot be culled at their old position. `dispose()` is idempotent and owns the injected textures, geometries, materials and InstancedMesh buffers.
- `textures.ts`: deterministic procedural wear, panels and hatch inscription. Browser-only generation is separate from the factory; unit tests inject synthetic DataTextures, not screenshots presented as real work.
- `studio.ts`: the approved seven-card procedural reflection environment, generated once per tier with PMREM. The temporary studio and PMREM generator are disposed immediately; the R3F model owns the resulting render target until cleanup. The previous scene environment is restored on unmount.
- `CompilerMachine.tsx`: `TB001Model` is a reusable R3F model driven by a preallocated pose callback. It creates resources in a committed layout effect, not during render/useMemo, so StrictMode setup/cleanup does not orphan GPU resources. `CompilerMachine` is the product adapter.

### Presentation

The provisional #19 adapter (global progress as `cycle`, six lateral slots) has been replaced by the #16 chapter
choreography and the #13 scheduler: see [MOTION.md](MOTION.md). `presentation.ts` maps chapter and stage progress to
`cycle`/`explode`, orientation and a camera fitted to the real geometry through `envelope.ts`.

The old 1.48π global spin is deliberately not copied: it would turn the approved front mechanism away from the visitor.

## High / low

| Setting | High | Low |
|---|---|---|
| Outer petal subdivisions | 30 × 34 plus chamfers | 15 × 17 plus chamfers |
| Ring angular segments | 96 | 48 |
| Reflection PMREM face size | 256 | 128 |
| Anisotropy / wear / bump | 0.55 / yes / yes | off / off / off |
| Panel color map | 512² | 256² |
| Hatch map | 512² | 512² |
| Procedural maps on model | 4 | 2 |
| Instanced groups | rivets, 3 slit groups, cage, 6 cage struts, 9 orbit nodes | same families; fewer slit instances |

No bloom, AO or shader warm-up is added (#22). The model must remain readable without them. The six materials on the core faces are retained to preserve their approved brightness differences; a new fresnel/transmission/triplanar shader is not substituted for the validated v0.4 look. The hatch marking remains a generated map, not physical engraved geometry.

The source SPEC table mentions eight cage struts, but the approved `machine.js` actually renders **three per pole, six total**. The port follows that rendered geometry and instances the six struts. Other dimensions, pivots, motion windows and core brightness match the approved spike.

## Verification commands

```sh
pnpm check
pnpm exec playwright test --project=chromium --project=webkit --workers=2
```

The unit suite includes:
- recorded v0.4 pose parity, endpoints, intermediate states, state boundaries, input normalization, stable reusable references and reverse-path independence;
- a 501-pose replay of the approved film **per tier**, testing all vertices of tagged solids and camera-facing core visibility (≥0.9 during the established exposed-core window, ≥0.95 in the teardown hold);
- the known-bad rear twist at 34° during opening, which must produce the two known collision pairs;
- finite shell positions/normals/UVs, stable object/resource identities, instance-bound refresh, correct triangle accounting, and idempotent resource disposal.

These are analytic/raycast geometry tests, not GPU timing or physical certification. As in #18, edge/edge-only crossings can escape a vertex probe. Rivets, gimbal pins, cage/struts and graphic layers are not collision-scanned. Contacts belonging to actual joints are explicitly excluded with the same solid identities as the spike.

### Component-level browser review

Start a dedicated dev server in this checkout (strict port avoids reusing somebody else's app):

```sh
pnpm exec vite --host 127.0.0.1 --port 4200 --strictPort
```

In another terminal:

```sh
TB001_REVIEW_OUT=test-results/tb001-review/run-1 \
CHROMIUM="/path/to/full/Chrome for Testing" \
node tests/review/tb001.mjs
```

`TB001_REVIEW_URL` may override the loopback origin. Without `CHROMIUM`, Playwright uses its installed Chromium; record whether this is hardware or a software/headless profile. On macOS, full Chrome for Testing is the verified WebGL path; do not infer a physical mobile GPU from a 390px viewport.

The dev-only fixture renders the **actual R3F model component** in StrictMode. The runner captures 01–04 and teardown at 1440×900 and 390×844 for both tiers, checks actual projected vertices for clipping, checks collisions/core rays, records real renderer calls/triangles and probes unmount/remount on the same renderer. Geometry/texture counts must release on unmount and remain stable through three remounts. One renderer-owned fallback texture may remain. Record sources are SHA-256 fingerprinted before and after the run. The fixture and probe helpers are not part of the production import graph.

The review camera matches the spike on desktop. In portrait only, the independent exploded pose uses an additional 12.5% pullback to avoid the right-edge crop found in #18. That camera is a review composition, not a shipped scroll mapping; shipped chapter framing is documented in [MOTION.md](MOTION.md).

## Handoff

- #12 owns the full-page deterministic visual/probe harness. #19 supplies stable pure inputs and a component fixture; neither owns a second animation scheduler.
- #13 (done, [MOTION.md](MOTION.md)) owns idle scheduling and pause UI. Do not switch this canvas to `always` merely to make TB-001 breathe.
- #14 may extract/refine the environment, but should not re-polish the removed scene.
- #16 (done, [MOTION.md](MOTION.md)) consumes `cycle` / `explode` through the model driver; regenerate `envelope.ts` after any geometry or pose change.
- #20 consumes stable part IDs/pose output for truthful HUD/callouts.
- #22 owns final tier/performance decisions, warm-up and optional post.

No commit, push, deployment or issue closure is implicit in these local changes. The final review must distinguish the verified model from unfinished page choreography.
